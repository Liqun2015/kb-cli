# Task Lifecycle

`LLM/tasks/` and `LLM/memory/` form the handoff and audit trail for work that deterministic commands intentionally do not complete.

The goal is to prevent hidden LLM work. A command should finish what it can do deterministically, then clearly describe what remains.

## Task locations

```text
LLM/tasks/index.md
    Manager LLM task dashboard generated by `kb tasks`.

LLM/tasks/items/<task_id>.md
    Bounded Worker LLM / human task files generated by `kb tasks`.

LLM/tasks/llm_tasks_<timestamp>.md
    Timestamped handoff snapshots generated by `kb tasks`.

LLM/tasks/
    Also stores explicit audit-review prompts and other handoff files from future deterministic commands.

LLM/memory/
    Completed-task records created with `kb memory` after human, Manager LLM, or Worker LLM work has been reviewed.
```

## Recommended status vocabulary

| Status | Meaning | Typical owner |
|---|---|---|
| `pending` | The task has been generated but not assigned. | Manager LLM / human maintainer |
| `assigned` | A human or Worker LLM has been asked to work on it. | Manager LLM |
| `in_progress` | The task is actively being worked on. | Worker LLM / human |
| `needs_human` | A final decision requires human judgment. | human reviewer |
| `blocked` | The task cannot proceed because required data, text, or source files are missing. | Manager LLM / human |
| `completed` | The task has been completed and recorded in `LLM/memory/`. | human / Manager LLM |
| `rejected` | The proposed task or relation was inspected and intentionally not accepted. | human / Manager LLM |

## Minimum task fields

Every task handoff should include:

```text
id
category
target_agent
goal
requirements
files
evidence
source_command
priority
```

For literature relationship work, the task should also preserve:

```text
relation_type
status
confidence or score when available
needs_human_review
source file and line evidence
```

## Minimum completed-memory fields

Every completed task memory should record:

```text
task_id
title or short description
summary
files touched or produced
source task file if available
follow-up issues if any
timestamp
```

`kb memory` is intentionally simple. It records what was done; it does not prove that the work is scientifically correct.

## Manager / Worker responsibility split

The Manager LLM or human maintainer should:

1. Run deterministic commands such as `grep`, `query`, `refs`, `refs-index`, `links`, and `lint-static`.
2. Open `LLM/tasks/index.md` as the task dashboard.
3. Select one pending task or topic review queue.
4. Assign one bounded `LLM/tasks/items/<task_id>.md` file to a Worker LLM or human reviewer.
5. Review Worker output with Git diff.
6. Record accepted results with `kb memory`.

A Worker LLM should:

1. Receive one bounded task file, usually from `LLM/tasks/items/<task_id>.md`.
2. Work only on the listed files unless explicitly instructed otherwise.
3. Preserve evidence lines and uncertainty.
4. Return clear changes, unresolved issues, and follow-up recommendations.

## Human final guarantee

Bibliographic index relations are special. Rust-native commands can find `confirmed`, `candidate`, `ambiguous`, and `missing` relation candidates, but uncertain bibliographic identity decisions need human review.

Human review is the final guarantee when reference formats differ, DOI metadata is missing, titles vary, author lists are abbreviated, or multiple local papers look similar.
