# Interface Directory Boundary

LLM Wiki keeps durable knowledge separate from generated interface artifacts used for human-machine interaction and machine-machine handoff.

## Durable knowledge layer

These paths are part of the knowledge base source of truth:

- `raw/`
- `wiki/`
- `topics/`
- `processing/`
- `LLM/tasks/`
- `LLM/memory/`
- `rules/`
- `llm-wiki.toml`
- `AGENTS.md`, `CLAUDE.md`, and handoff files

Agents and humans should write accepted knowledge decisions back to these Markdown/JSON/TOML files.

## Interface artifact layer

`interfaces/` is the single directory for generated, non-source interface artifacts:

- `interfaces/html/` — browser review pages generated by `kb check`
- `interfaces/reports/` — health, lint, and audit reports
- `interfaces/logs/` — generated metadata and operational logs
- `interfaces/answers/` — generated answers or temporary results
- `interfaces/figures/` — generated figures
- `interfaces/slides/` — generated slides

Files under `interfaces/` may be deleted and regenerated. They are useful for review, diagnostics, human-friendly inspection, and agent handoff, but they are not the source of truth.

## Agent rule

An LLM agent may inspect `interfaces/` to understand the current state, but must not treat generated HTML, reports, or logs as final knowledge. If a decision is made while reviewing an artifact, the result must be written back to the appropriate durable Markdown/JSON/TOML source file outside `interfaces/`.

## Check rule

`kb check` creates interface HTML artifacts. These pages can visualize relationships, tasks, sections, or reports, but they cannot by themselves confirm a relation, accept a claim, or change the Wiki.
