# `kb extract-sections`

`kb extract-sections` slices the `Introduction` and `References` sections from extracted paper text.

These two sections are important inputs for literature relationship work:

- `Introduction` often states the research gap, motivation, and foundational citations.
- `References` exposes the explicit citation boundary of the paper.

The command is deterministic. It does not call OCR or an LLM by itself.

## Usage

```bash
kb extract-text
kb extract-sections
kb extract-sections --dry-run
kb extract-sections --json
kb extract-sections --force
kb extract-sections --path processing/text/raw__papers__example.txt
```

## Inputs

Default input:

```text
processing/text/
```

The command expects plain text generated by `kb extract-text` or by an explicit OCR/LLM Worker.

## Interfaces

Default output:

```text
processing/sections/<source-key>/
├── introduction.txt
├── references.txt
└── section_manifest.md
```

`section_manifest.md` records whether each section was found, the detected line range, character count, and whether the slice looks usable or suspiciously short.

## LLM/OCR fallback

If one or both sections are missing or too short, the command writes an explicit fallback task under:

```text
LLM/tasks/items/paper-section-extraction-<timestamp>.md
```

That task is intended for a `Paper Section OCR/LLM Worker`.

The Worker should recover the missing sections from image-based PDFs, scanned papers, or bad text extraction outputs, then write:

```text
processing/sections/<source-key>/introduction.txt
processing/sections/<source-key>/references.txt
processing/sections/<source-key>/section_manifest.md
```

## Boundary

`kb extract-sections` does not:

- perform OCR automatically;
- call an LLM automatically;
- summarize the sections;
- decide citation identity;
- infer scientific relationships among papers;
- rewrite `wiki/` pages.

It only creates high-value section text for later reference reconciliation, topic ranking, and LLM-assisted literature relationship review.
