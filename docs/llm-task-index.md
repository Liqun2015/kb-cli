# LLM Task Index

`LLM/tasks/index.md` is the Manager LLM task dashboard.

It is generated by:

```bash
kb tasks
```

The index does not run an LLM. It organizes deterministic findings into a reviewable task-routing document so a Manager LLM or human maintainer can decide what should happen next.

## Purpose

Before `v0.7.3`, task material was useful but scattered:

```text
LLM/tasks/*.md
processing/proposals/prepare_agent_prompt_*.md
topics/<topic>/review/review_queue.md
outputs/reports/*.md
```

Starting in `v0.7.3`, `kb tasks` makes the Manager LLM entry point explicit:

```text
LLM/tasks/index.md
```

The index answers:

- What pending Worker task items exist?
- Which task file should a Worker LLM open?
- Which topic review queues need attention?
- Which prepare prompts are available for source-to-Wiki work?
- Which older task or audit reports exist?
- What should the Manager LLM do next?

## Generated files

Default command:

```bash
kb tasks
```

writes:

```text
LLM/tasks/index.md
LLM/tasks/items/<task_id>.md
LLM/tasks/llm_tasks_<timestamp>.md
```

### `LLM/tasks/index.md`

This is the Manager LLM dashboard.

It includes:

- generated time
- current handoff snapshot path
- pending Worker task table
- topic review queue table
- prepare agent prompt table
- existing task/audit report table
- Manager LLM operating rules
- recommended Manager → Worker → human review loop

### `LLM/tasks/items/<task_id>.md`

These are bounded Worker LLM / human task files.

Each item includes:

- task id
- status
- priority
- category
- target agent
- source command
- goal
- requirements
- input files
- evidence
- Worker output rules
- completion command template

Worker LLMs should receive one item file at a time.

### `LLM/tasks/llm_tasks_<timestamp>.md`

This remains the timestamped audit snapshot of the current `kb tasks` scan.

It is useful for review history and debugging, but the Manager LLM should normally start from `LLM/tasks/index.md`.

## Useful modes

```bash
kb tasks
kb tasks --dry-run
kb tasks --json
kb tasks --index-only
kb tasks --no-index
```

### `--index-only`

Refreshes:

```text
LLM/tasks/index.md
LLM/tasks/items/<task_id>.md
```

without writing a new timestamped `llm_tasks_<timestamp>.md` snapshot.

Use this when the Manager LLM dashboard should be updated without adding another historical report.

### `--no-index`

Preserves the older behavior and writes only the timestamped handoff report.

Use this when you want a report snapshot but do not want to change the Manager LLM task dashboard.

## Manager / Worker handoff

Recommended flow:

```text
Manager LLM opens LLM/tasks/index.md
        ↓
selects one pending task or topic review queue
        ↓
assigns one bounded task item to a Worker LLM or human reviewer
        ↓
Worker LLM works only on listed files and preserves evidence / uncertainty
        ↓
human or Manager LLM reviews the output with Git diff
        ↓
accepted work is recorded with kb memory
```

## Boundary

`LLM/tasks/index.md` is a routing document.

It does not:

- call an LLM
- execute Worker tasks
- accept or reject scientific claims
- edit Wiki pages
- replace human review

It only makes the task intake point clear enough for a Manager LLM to begin work safely.


## Section extraction task intake

Starting in `v0.7.4`, the Manager LLM task index may include:

```text
paper-section-extraction-001
```

This task means that deterministic section slicing did not produce usable `Introduction` and `References` files under `processing/sections/`. The Manager LLM should assign it to a `Paper Section OCR/LLM Worker`, not to a relationship-interpretation Worker. The goal is section capture, not summary or scientific judgment.
